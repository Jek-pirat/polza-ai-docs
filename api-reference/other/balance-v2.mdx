Версия 2 отличается от [`GET /v1/balance`](/api-reference/other/balance) семантикой поля `amount`: здесь это всегда полный баланс организации (кошелёк), а сколько именно можно потратить — отдельное поле `available`. Используйте v2 в новом коде.

## Примеры

<CodeGroup>
```bash cURL
curl "https://polza.ai/api/v2/balance" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```python Python
import requests

response = requests.get(
    'https://polza.ai/api/v2/balance',
    headers={'Authorization': 'Bearer YOUR_API_KEY'}
)

data = response.json()
print(f"Баланс: {data['amount']} руб., доступно: {data['available']} руб.")
```

```javascript JavaScript
const response = await fetch('https://polza.ai/api/v2/balance', {
  headers: { 'Authorization': 'Bearer YOUR_API_KEY' }
});

const data = await response.json();
console.log(`Баланс: ${data.amount} руб., доступно: ${data.available} руб.`);
```
</CodeGroup>

## Ответ (200)

```json
{
  "amount": "1234.56000000",
  "available": "1200.06000000",
  "reservedAmount": "12.50000000",
  "spentAmount": "845.30000000",
  "updatedAt": "2026-04-30T12:00:00.000Z"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `amount` | string | Баланс организации в рублях (кошелёк). Всегда полный остаток, без учёта лимитов |
| `available` | string | Доступно к трате: остаток за вычетом резерва под выполняющиеся запросы, не больше остатков лимитов расходов ключа и участника |
| `reservedAmount` | string | Зарезервировано под выполняющиеся запросы. Не возвращается, если у участника, на которого выпущен ключ, задан личный лимит расходов |
| `spentAmount` | string | Потрачено организацией за всё время. Не возвращается при личном лимите участника |
| `updatedAt` | string | Время последнего обновления баланса (ISO 8601) |

Все суммы — строки с восемью знаками после точки. Для проверки «хватит ли денег на запрос» ориентируйтесь на `available`: во время выполняющихся запросов оно меньше `amount` на сумму резерва и снова сравнивается с ним после завершения.

## Резерв и параллельные запросы

Перед выполнением запроса на балансе резервируется его оценочная стоимость. После ответа списывается фактическая стоимость, а резерв сразу освобождается. Поэтому одновременно выполняются только те запросы, чьи резервы в сумме помещаются в баланс. Следующий запрос сверх этого получит `402`.

Резерв одного запроса к текстовой модели складывается из стоимости входных токенов и `max_tokens` (если он не задан — 2048 токенов) по цене модели, с небольшим запасом. Для медиа-моделей с фиксированной ценой резерв равен этой цене.

Пример: резерв запроса — 3 ₽, баланс — 30 ₽. Одновременно пройдут 10 запросов, 11-й получит `402`, пока один из первых не завершится.

Как держать параллельность под контролем:

- Новый запрос пройдёт, если его резерв не больше `available`. `reservedAmount` показывает, сколько сейчас занято под выполняющиеся запросы.
- В тексте ошибки `402` указаны резерв запроса («Требуется»), доступная сумма и уже зарезервированная.
- Задавайте `max_tokens` по реальной длине ответа: чем он меньше, тем меньше резерв и тем больше запросов можно выполнять одновременно.
- На `402` при параллельной нагрузке отвечайте короткой паузой и повтором: резерв освободится, когда завершатся текущие запросы.

`402` также возвращается, когда исчерпан лимит расходов ключа или участника. Тогда в тексте ошибки говорится о превышении лимита.

<Note>
Ответ кэшируется на 1 секунду и не резервирует деньги, поэтому между проверкой `available` и отправкой запроса его могут занять другие запросы. Пополнить баланс можно в [консоли](https://polza.ai/dashboard) через банковскую карту, СБП или счёт для юридических лиц.
</Note>
